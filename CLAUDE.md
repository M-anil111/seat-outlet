# CLAUDE.md: Seat Outlet

Read `README.md` first (run, test, deploy, where errors go) and `CONTRIBUTING.md` (the long guide). This file is the map of the system and the rules that are easy to break.

## What it is

A PHP 8.1+ ticket marketplace on MariaDB/MySQL. Ticket data, prices, seat maps and checkout come from TicketNetwork (TN). There is no framework. `vendor/` is committed on purpose (nothing is resolved at deploy time); `tools/test-vendor-lock.php` checks it matches `composer.lock`.

## Map

| Path | Job |
|---|---|
| `*.php` in the root | Pages. Most are 3 to 5 line wrappers that call a renderer in `inc/` (`event.php`, `performer.php`, `venue.php`, `city.php`, `category.php`, `checkout.php` are the real ones). Legacy URLs 301 to the current page. |
| `functions.php` | The bootstrap and a very large shared library (6,800+ lines, 270 functions: TN requests and caching, layout, markup, SEO helpers). New code goes in `inc/`, not here (`docs/refactor-plan.md`). |
| `inc/` | Everything else: `tn-budget.php` (call budget), `tn-bulk*.php` (local copy of the TN catalog), `slugs.php` (URL slugs), `seo-*.php` and `page-spec.php` (titles, H1, descriptions), `leads-core.php` (sign-ups), `images.php`, `csp.php`, `auto-migrate.php`, `cron-report.php`. |
| `ajax/` | JSON endpoints (home feeds, suggestions, sign-up, order webhook, health, vitals, CSP reports). |
| `admin/` | The CMS (blog, page rules, images, contact messages). Every page calls `admin_require_login()`; every state change verifies a CSRF token; sign-out is a POST. |
| `cron/` | Scheduled scripts, run as `php cron/<name>.php`, never by URL. Each calls `soCronWatch()` so a failure reaches the error log and Sentry. |
| `db/` | `config.php` (connection; throws on every failed query), `migrate.php`, `migrations/*.sql` (applied once, in filename order, tracked in `schema_migrations`). |
| `deploy/` | `pull-deploy.sh` (cron on the server), config and env examples, `nginx/seatoutlet.com.vhost` (the live CloudPanel Vhost). |
| `tools/` | Tests (`test-*.php`, `test-*.mjs`), checks, asset and critical-CSS builders. `.github/workflows/ci.yml` runs them. |
| `css/`, `js/` | Source files. Minified and per page-type bundles are built by `tools/build-assets.sh`; critical CSS in `css/critical/` is generated by `tools/critical-css.cjs`. |
| `cache/` | Runtime cache and page snapshots written by the site. Never delete or reset it on a live server. |
| `docs/` | Runbooks: `production-safeguards.md` (how live is served: CloudPanel, nginx, PHP, no Cloudflare Worker; server checklist), `pull-deploy.md`, `reliability.md` (TN limits, snapshots, what happens when TN is slow), `csp.md`, `secret-rotation.md`, `ticketnetwork-api.md`, `server-rewrites.md`. |

## Rules that matter

- **TN call budget.** TN allows about 50 calls a minute; the site spends 0.75 a second (`TN_CALLS_PER_SECOND`). A page that needs TN data and cannot get it answers from a saved copy, then from the local bulk copy (`tn_bulk_events`), and only then with a 503. Never add a TN call on a hot path without reading `docs/reliability.md`. Never start a full TN import or touch the hourly bulk cron without the owner's approval.
- **Migrations are deliberate.** Do not run migrations against production, and do not turn on `SO_AUTO_MIGRATE` there. The deploy dumps the database first when a migration is pending.
- **Secrets.** Names only in the repository (`.env.example`). Values live in the server's `inc/env.local.php` and in GitHub Actions secrets. Never print, log or commit a value. Never delete or overwrite production credentials.
- **Database errors are loud.** `db/config.php` makes mysqli throw. Code that must survive a failure (lead sign-up, alerts) wraps its own try/catch and logs; do not swallow exceptions silently.
- **Public output.** No raw exception, query or stack trace in a response. The public health page shows only `ok`, `time` and `commit`.
- **SQL.** Prepared statements only. Where a clause is built dynamically (`admin/images.php`, `inc/tn-bulk-read.php`), the pieces come from a fixed list or an integer cast.
- **CSP** is report-only on production (`docs/csp.md` has the checklist for enforcing it). Inline scripts need the per-request nonce.
- **Do not edit generated files by hand:** `css/critical/*.css`, `css/style.*.min.css`, `js/*.min.js` (rebuild them), `vendor/` (use composer).

## Working rules (from the owner)

- Changes go on a branch and a pull request; the owner says "merge". CI must be green first.
- Commit messages end with the `Claude-Session:` line given by the session and carry no model name.
- Keep fixes small and tested; add or extend a `tools/test-*.php` for every fix and list it in `ci.yml`.
- Anything that changes a production setting, deletes files or data, or is hard to undo needs the owner's explicit approval first.

## Checks before a pull request

`php tools/check-env.php`, the test loop in `README.md`, `php tools/check-arg-counts.php .`, `php tools/check-undefined-functions.php .`, `composer audit`.
